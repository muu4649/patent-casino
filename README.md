# 特許カジノ

水曜日のダウンタウン「チューブカジノ」の特許版。
**発明の名称だけを見て、請求項1〜2に登場する単語を予想してチップを賭ける**パーティゲーム。

**収録 161 問**（実在特許 158 問＋動作確認用の架空 3 問）。
実在特許は Google Patents から請求項1〜2を取得したもので、出典URLをゲーム内に表示する。

## 遊び方

`index.html` をダブルクリックするだけ。サーバー不要、通信なし、単一ファイルで完結する。

1. 人数（2〜4人）・初期チップ・ラウンド数を決める
2. **手番交代画面**（全面ブラックアウト）で端末を次の人へ渡す。本人が輪を長押しして開始
3. 発明の名称／出願人／出願年／IPC を見て、**12ワードから最大3語をタップ**して選ぶ
4. `1` `3` `5` `MAX` のチップボタンで枚数を決めて **BET確定**
5. 全員終わったら **開票** → **収支** → **答え合わせ（請求項全文）** の順に発表
6. 全ラウンド終了時、チップが最も多い人の勝ち

1台の端末を回して遊ぶことを想定している。前の人の賭けは交代画面で隠れる。

### ルールの要点

| 項目 | 値 |
|---|---|
| ボード | 12ワード（**実際に出るのは4語だけ**、残り8語は罠） |
| 賭けられるワード数 | 1ラウンド3ワードまで |
| 賭けられる枚数 | 1ラウンドで所持チップの半分まで（最低3枚） |
| 破産救済 | 0枚になったら次ラウンド開始時に3枚支給 |

罠の語にも正解語と**同じオッズ帯**を振ってある。オッズを見ても正解は分からない。

## 面白さの核

日常語と明細書用語のズレが罠になっている。

- 回転寿司なのに「レーン」は出ない（明細書では**コンベヤ**）
- 折り畳み表示装置なのに「折り目」は出ない（明細書では**湾曲領域**）
- どの明細書にもありそうな「制御部」「検出」が、その特許には無い

## UI方針

「単語を予想する」以外の操作にコストを使わせないことを優先している。

- **BETは2手**：ワードをタップ → チップ額（`1` `3` `5` `MAX`）を押すだけ。増減ボタンの連打はしない
- **チップ操作と確定はベットスリップに集約**：選んだ語・チップ・残り枚数・確定ボタンを画面下のドックに固定し、盤面をスクロールしても親指の位置で操作できる。PCではドックを本文の幅に揃えて1列に並べる
- **制約は見れば分かる状態にする**：`3 / 3 WORDS SELECTED` と使用枚数のメーターを常時表示し、3語選んだ時点で残りのカードを自動的に薄くして押せなくする。警告で初めて知らせる作りにしない
- **手番交代は全面ブラックアウト＋長押し**：BET確定と同じ瞬間に不透明な交代画面を出し、背後の盤面は消しておく。前の人の賭けは1フレームも見えない。長押しは円形のリングが進み、途中で離すとリセット。キーボードは Space 長押し
- **発表は3段階**：開票 → 収支 → 請求項全文。請求項を最初に見せると盛り上がりが止まるため、答え合わせの解説として最後に置く。開票中は上部のチップ表示を精算前の値に留め、結果を先に漏らさない
- **スマホファースト**：ワードは2列（600px以上で4列）、タップ領域56px以上、Safe Area 対応
- **開始前の説明は3行**：細かいルールは折りたたみに入れ、必要な場面でUI側が処理する

## デザインと演出

ダークグリーン・ブラック・ゴールドを基調に、グラデーション・透明度・多層シャドウで奥行きを出している。

| 用途 | 色 |
|---|---|
| 背景 / カード / 強調面 | `#071510` / `#102820` / `#19382E` |
| ゴールド / 光沢 | `#D7B866` / `#F5DC99` |
| 的中 / 不的中 | `#42D6AE` / `#FF6B7A` |
| 文字 / 補助文字 | `#F5F2E9` / `#AAB8B0` |

- 背景は複数の放射グラデーション、28〜34秒周期でゆっくり動く光、薄いノイズ（起動時に canvas で生成）を重ねている。ゲーム内容より目立たないよう動きは遅く、薄くしている
- パネルは角丸20px・半透明グラデーション・上辺だけ光る金の縁取り。ホバーで浮き、押すと沈む（ホバーできない端末では選択状態を色と番号で示す）
- 外部フォントは読み込まない。日本語はヒラギノ／Noto Sans JP 系、数字は system-ui の等幅数字。請求項の本文だけは公報らしさを残すため明朝体
- 主な演出

| 場面 | 演出 |
|---|---|
| 開始 | タイトルの金のグラデーションと発光、背後で回る光のリング、開始ボタンを横切る光 |
| 手番交代 | プレイヤー色の後光、長押しで進む光のリング、完了時の発光と火花 |
| BET | カードの配布アニメーション、選択時の金の発光と番号バッジ、チップ投入時の枚数の弾みとカードの発光、残り枚数メーター |
| 開票 | 1語ずつ判定スタンプ。的中はエメラルドの発光、外れは赤い×と取り消し線。8倍以上の的中は BIG WIN 表示・金の火花・紙吹雪。タップでスキップ |
| 収支 | カードが上から順に出て、増減と合計がカウントアップ。最も稼いだ人に TOP |
| 最終結果 | 王冠・金のグロー・紙吹雪・チップ数のカウントアップ。同点優勝は「DRAW ・ 同点優勝」で全員を表示し、順位は 1,1,3 方式 |

- アニメーションは `transform` と `opacity` が中心。`prefers-reduced-motion` を有効にしている端末では、動き・紙吹雪・カウントアップを止めて結果だけを表示する
- 演出は `FX` モジュールに分けてあり、ゲームの状態には触らない。演出用の乱数も `Math.random` とは別系統なので、演出の有無で出題や盤面は変わらない
- ゲームの規則は `src/template.html` の `GAME LOGIC` 区間に純粋関数として切り出してある

## オッズ設計

`オッズ = 1 / 出現確率` を4層で見積もっている。

| 層 | 倍率 | 例 |
|---|---|---|
| 汎用語（どの明細書にもある） | 1.2〜2.0 | 所定、制御部、検出 |
| 名称由来（発明の名称に含まれる） | 1.3〜2.0 | 搬送、表示 |
| 分野語（その技術分野なら出そう） | 2.5〜7 | コンベヤ、ヒンジ、可撓性 |
| レア語（出るが予想しにくい） | 8〜30 | 寿司ネタ、曲率半径、退避空間 |

### バランス検証結果

`_drafts/simulate.py` で1問あたり4,000回シミュレーションした、3枚投入時の平均収支。

| ボード構成 | ランダムに賭ける人 | 正解語を見抜く人 |
|---|---|---|
| 正解5・罠5（初期案） | **+7.64** | +27.67 |
| **正解4・罠8（採用）** | **+2.66** | +18.15 |

初期案は的中率50%に対して平均オッズ5.4〜7.2倍と高すぎ、賭けるほど増えるのでカジノとして成立していなかった。
正解4・罠8（的中率33%）に変更して是正した。3ワード賭けて平均1.0語が的中する。

## 出題のランダム性

出題順もボードの12語も、ゲーム開始のたびにシャッフルされる。固定シードは使っていない。

さらに**直前のゲームで出した問題は後回しにする**（localStorage に記録し、未出題の問題を優先）。
収録が少ないと「またこの問題か」が起きやすいため。

161 問あるので、1ゲーム3〜10ラウンドなら当分は同じ問題に当たらない。

## 問題を追加する

やり方は3つある。**いちばん簡単なのは A**。

### A. 請求項をコピペする（推奨）

```bash
python3 make_question.py
```

対話形式で聞かれるので、順に答えるだけ。

```
発明の名称: 回転寿司用皿搬送装置
出願人（任意、Enterで空欄）: 株式会社サンプル
出願年（任意 例 2023）: 2023
IPC（任意 例 A47F 10/06）: A47F 10/06
ヒント（任意。画面に出る一言）: 厨房設備の発明です
公開番号など（任意 例 JP6935980B2）: JP6935980B2

請求項1の本文:
  （貼り付けたら、空行を2回入れるか . だけの行で確定）
複数の皿を載置して循環搬送する無端状のコンベヤと、
...
```

J-PlatPat や Google Patents から請求項をコピーして貼り付ければよい。あとは自動で、

1. 請求項に出てくる語を抜き出して**正解語**にする
2. 収録済み特許のうち**語彙が似ているもの**から、この請求項には出ない語を選んで**罠語**にする
3. 両方に、収録データ全体での出現頻度から**オッズ**を付ける

`data/questions_custom.json` に保存されるので、最後に反映する。

```bash
python3 build.py
```

保存前に「このままでは遊べません」と警告が出たら、何が足りないかが具体的に表示される。
JSONを開いて `words` に語を足せばよい（後述の必須要件を参照）。

### B. Google Patents からまとめて取り込む

特許番号のリストがあるなら、こちらのほうが速い。

```bash
python3 _drafts/20260830_1010_fetch_claims_v1.py    # 請求項を取得（レジューム可）
python3 _drafts/20260831_build_questions_v1.py      # 問題JSONを生成
python3 build.py                                    # ゲームに反映
```

取得対象は `_drafts/20260830_0950_ids_v1.json` に入っている。
別の特許を対象にしたいときは `_drafts/20260830_0950_collect_ids_v1.py` の `THEMES` を書き換えて実行する。

Google Patents は連続アクセスすると **HTTP 503 でIP単位でブロックされる**。
取得間隔は3秒にしてある。ブロックされたら時間をおいて再実行すれば、取得済みはスキップされ途中から再開する。

### C. JSONを手で書く

`data/` に置いた `*.json` はすべて読み込まれる。`data/_template.json` をコピーして書き換えるのが早い。

```json
{
  "schema_version": 2,
  "items": [
    {
      "id": "JP6935980B2",
      "source": "real",
      "num": "JP6935980B2",
      "title": "発明の名称",
      "assignee": "出願人",
      "date": "2019",
      "ipc": "B62D 25/08",
      "hint": "画面に出るヒント（任意）",
      "url": "https://patents.google.com/patent/JP6935980B2/ja",
      "claims": [
        { "num": "1", "text": "請求項1の全文" },
        { "num": "2", "text": "請求項2の全文" }
      ],
      "words": [
        { "w": "搬送",   "odds": 1.4, "tier": "title" },
        { "w": "レーン", "odds": 2.8, "tier": "trap" }
      ]
    }
  ]
}
```

**正解フラグは書かない。** `words` の各語が請求項本文に含まれるかを実行時に文字列マッチで判定する。
つまり「請求項に出る語」を書けば正解語、「出ない語」を書けば罠語になる。`tier` は設計メモで、ゲームは見ていない。

### 必須要件

これを満たさないとボードが作れず、その問題は自動的に除外される（`build.py` が警告する）。

| 要件 | 数 | 理由 |
|---|---|---|
| 請求項本文に**出る**語 | 4語以上（推奨8語） | ボードに4語出すため |
| 請求項本文に**出ない**語 | 8語以上（推奨12語） | ボードに8語出すため |
| 各オッズ帯に正解語と罠語の**両方** | 低 <2.5 ／ 中 2.5〜7 ／ 高 >7 | 片方に寄るとオッズを見ただけで正解が割れる |

推奨数を満たしておくと、同じ問題でも毎回違うボードになる。

### 確認する

```bash
python3 _drafts/validate.py data/questions_custom.json
```

帯ごとの内訳が出る。`検証エラー: 0` なら問題ない。

### つまずきやすいところ

- **「オッズ帯に罠語がありません」** — 低オッズ帯に罠がないと「安いオッズは必ず当たる」と読まれる。
  その特許に**出ていない**汎用語（「制御部」「検出」など）を低オッズで足すとよい。
  実際「読取部・計時部はあるのに制御部は無い」という明細書は多く、良い罠になる。
- **語が長すぎる** — 12文字を超える語は自動で捨てている。カードからはみ出すため。
- **「前記〜」が語に混ざる** — 自動抽出では先頭の「前記」「上記」「当該」を剥がしている。手で書くときも外すこと。
- **問題を消したい** — `data/` から該当のJSONを消すか、`items` から該当項目を削って `python3 build.py`。


## 収録データの出所

Google Patents から日本語の請求項1〜2を取得している。18テーマ（回転寿司・自動改札・温水洗浄便座・
即席麺・ゲームコントローラ・ドローン・洗濯乾燥機・電動アシスト自転車・ペット用トイレ・傘・カラオケ・
自動販売機・二次元コード・折り畳み表示装置・コーヒー抽出・空気調和機・電気かみそり・使い捨ておむつ）
で検索し、196件取得して 158 件を採用した。

採用にあたって次を満たさないものは自動的に外している。

- 請求項1〜2の合計が 120〜1400 字（短すぎると語が足りず、長すぎると読む負担が大きい）
- 発明の名称が 40 字以内（カードで崩れる）
- 正解語4語・罠語8語以上が確保でき、各オッズ帯に両方が揃うこと

**オッズは実測値から出している。** 収録した全請求項を1つのコーパスとして、各語が何件の請求項に
出るか（DF）を数え、その順位を 1.2〜30倍 に指数的に写像している。ありふれた語ほど安く、
その特許固有の語ほど高くなる。発明の名称に含まれる語は予想しやすいので 0.55倍して割り引く。

**罠語は「語彙が似ている特許に出るが、この特許には出ない語」から選ぶ。** 検索テーマのラベルは
当てにならない（無関係な特許が検索に混ざるため、電力制御の特許に「便座」が罠として付く事故が起きた）。
請求項の語彙で類似度を測り、近い6件から拾っている。

## Streamlit版

ゲーム本体は `index.html` で、`app.py` はそれを配信するだけのラッパー。

```bash
pip install -r requirements.txt
streamlit run app.py
```

Streamlit のウィジェットで組み直すと1タップごとにサーバー往復と全画面再描画が入り、
パーティゲームとしてのテンポが失われる。そのため**操作はすべてクライアント側で完結**させ、
Streamlit は配信だけを担当させている。

Streamlit Community Cloud にデプロイするときの設定値。

| 項目 | 値 |
|---|---|
| Repository | `muu4649/patent-casino` |
| Branch | `main` |
| **Main file path** | **`app.py`** |

`index.html` は生成物。編集するのは `src/template.html` で、変更後は `python3 build.py` を実行する。
