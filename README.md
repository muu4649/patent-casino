# 特許カジノ

水曜日のダウンタウン「チューブカジノ」の特許版。
**発明の名称だけを見て、請求項1〜2に登場する単語を予想してチップを賭ける**パーティゲーム。

## 遊び方

`index.html` をダブルクリックするだけ。サーバー不要、通信なし、単一ファイルで完結する。

1. 人数（2〜4人）・初期チップ・ラウンド数を決める
2. **手番交代画面**（全面ブラックアウト）で端末を次の人へ渡す。本人が輪を長押しして開始
3. 発明の名称／出願人／出願年／IPC を見て、**12ワードから最大3語をタップ**して選ぶ
4. `1` `3` `5` `MAX` のチップボタンで枚数を決めて **BET確定**
5. 全員終わったら **開票** → **収支** → **答え合わせ（請求項全文）** の順に発表
6. 全ラウンド終了時、チップが最も多い人の勝ち

1台の端末を回して遊ぶことを想定している。前の人の賭けは交代画面で隠れる。

### ルールの要点

| 項目 | 値 |
|---|---|
| ボード | 12ワード（**実際に出るのは4語だけ**、残り8語は罠） |
| 賭けられるワード数 | 1ラウンド3ワードまで |
| 賭けられる枚数 | 1ラウンドで所持チップの半分まで（最低3枚） |
| 破産救済 | 0枚になったら次ラウンド開始時に3枚支給 |

罠の語にも正解語と**同じオッズ帯**を振ってある。オッズを見ても正解は分からない。

## 面白さの核

日常語と明細書用語のズレが罠になっている。

- 回転寿司なのに「レーン」は出ない（明細書では**コンベヤ**）
- 折り畳み表示装置なのに「折り目」は出ない（明細書では**湾曲領域**）
- どの明細書にもありそうな「制御部」「検出」が、その特許には無い

## UI方針

「単語を予想する」以外の操作にコストを使わせないことを優先している。

- **BETは2手**：ワードをタップ → チップ額（`1` `3` `5` `MAX`）を押すだけ。増減ボタンの連打はしない
- **制約は見れば分かる状態にする**：`3 / 3 WORDS SELECTED` を常時表示し、3語選んだ時点で残りのカードを自動的に薄くする。警告で初めて知らせる作りにしない
- **手番交代は全面ブラックアウト＋長押し**：端末を渡す瞬間に前の人の賭けが見えない
- **発表は3段階**：開票（⭕❌）→ 収支 → 請求項全文。請求項を最初に見せると盛り上がりが止まるため、答え合わせの解説として最後に置く
- **スマホファースト**：ワードは2列、タップ領域56px以上、チップ残高と確定ボタンは画面下に固定
- **開始前の説明は3行**：細かいルールは折りたたみに入れ、必要な場面でUI側が処理する

## オッズ設計

`オッズ = 1 / 出現確率` を4層で見積もっている。

| 層 | 倍率 | 例 |
|---|---|---|
| 汎用語（どの明細書にもある） | 1.2〜2.0 | 所定、制御部、検出 |
| 名称由来（発明の名称に含まれる） | 1.3〜2.0 | 搬送、表示 |
| 分野語（その技術分野なら出そう） | 2.5〜7 | コンベヤ、ヒンジ、可撓性 |
| レア語（出るが予想しにくい） | 8〜30 | 寿司ネタ、曲率半径、退避空間 |

### バランス検証結果

`_drafts/simulate.py` で1問あたり4,000回シミュレーションした、3枚投入時の平均収支。

| ボード構成 | ランダムに賭ける人 | 正解語を見抜く人 |
|---|---|---|
| 正解5・罠5（初期案） | **+7.64** | +27.67 |
| **正解4・罠8（採用）** | **+2.66** | +18.15 |

初期案は的中率50%に対して平均オッズ5.4〜7.2倍と高すぎ、賭けるほど増えるのでカジノとして成立していなかった。
正解4・罠8（的中率33%）に変更して是正した。3ワード賭けて平均1.0語が的中する。

## 出題のランダム性

出題順もボードの12語も、ゲーム開始のたびにシャッフルされる。固定シードは使っていない。

さらに**直前のゲームで出した問題は後回しにする**（localStorage に記録し、未出題の問題を優先）。
3問しかないと「またこの問題か」が起きやすいため。

ただし**問題数がラウンド数以下だと、結局は全問出る**。
毎回違う問題に当たるようにするには、ラウンド数を問題数より少なくするか、問題を増やすこと。

## 問題データの追加

### 現状

**同梱の3問はすべて架空の明細書**（`source: "fictional"`、画面にも「架空・動作確認用」と表示される）。
実在特許を Google Patents から取得しようとしたが、**個別ページへの連続アクセスがIPブロック（HTTP 503）され、196件中0件しか取得できなかった**。
ローカルcurl・WebFetchの両方で遮断されており、復旧待ちの状態。

### 追加のしかた

方法は2つ。

**A. ゲーム内から読み込む**
設定画面の「問題データを読み込む」ボタンでJSONファイルを選ぶ。その場で差し替わる（同梱データは上書きされない）。

**B. ビルドして埋め込む**
`data/` にJSONを置いて再ビルドする。

```bash
python3 build.py
```

`data/*.json` の設問がすべてマージされ、`index.html` が再生成される（`id` が重複したものはスキップ）。

### JSONスキーマ

```json
{
  "schema_version": 2,
  "items": [
    {
      "id": "JP6935980B2",
      "source": "real",
      "num": "JP6935980B2",
      "title": "発明の名称",
      "assignee": "出願人",
      "date": "2019",
      "ipc": "B62D 25/08",
      "theme": "自動車",
      "hint": "画面に出るヒント（任意）",
      "url": "https://patents.google.com/patent/JP6935980B2/ja",
      "claims": [
        { "num": "1", "text": "請求項1の全文" },
        { "num": "2", "text": "請求項2の全文" }
      ],
      "words": [
        { "w": "搬送", "odds": 1.4, "tier": "title" },
        { "w": "レーン", "odds": 2.8, "tier": "trap" }
      ]
    }
  ]
}
```

**正解フラグは持たせていない。** 正解判定は `words` の各語が請求項本文に含まれるかの文字列マッチで実行時に行う。
そのため実データを流し込めば自動で答え合わせが効く。`tier` はオッズ設計用の内部ラベルで、プレイヤーには表示されない。

### データ作成時の必須要件

`build.py` が検証する。これを満たさないとボードが生成できない。

- 請求項本文に**含まれる語が4語以上**（推奨6語以上。少ないと毎回同じボードになる）
- 請求項本文に**含まれない語が8語以上**（推奨10語以上）
- 各オッズ帯（低 <2.5 ／ 中 2.5〜7 ／ 高 >7）に**正解語と罠語の両方**を置くこと
  — 片方に寄るとオッズを見ただけで正解が割れる

`_drafts/validate.py` で帯ごとの内訳を確認できる。

```bash
python3 _drafts/validate.py data/questions_sample.json
```

## 実データ取得の再開

Google Patents のブロックが解けたら、途中から再開できる。

```bash
python3 _drafts/20260830_1010_fetch_claims_v1.py
```

- 取得済みは `_drafts/20260830_1010_claims_v1.jsonl` に1件ずつ追記され、再実行時はスキップされる
- 検索で収集済みの特許ID 340件は `_drafts/20260830_0950_ids_v1.json` にある（18テーマ）
- 生存確認は `curl -o /dev/null -w "%{http_code}" https://patents.google.com/patent/JP7106160B2/ja`。200が返れば再開できる

取得後、請求項からキーワードを抽出してオッズを付ける工程が別途必要（未着手）。

    ├── validate.py             ← 問題データの整合性チェック
    ├── simulate.py             ← オッズ勾配のバランス検証
    ├── simulate2.py            ← ボード構成別の比較

`index.html` は生成物なので直接編集しないこと。`src/template.html` を直して `python3 build.py` を実行する。

## Streamlit版

ゲーム本体は `index.html` で、`app.py` はそれを配信するだけのラッパー。

```bash
pip install -r requirements.txt
streamlit run app.py
```

Streamlit のウィジェットで組み直すと1タップごとにサーバー往復と全画面再描画が入り、
パーティゲームとしてのテンポが失われる。そのため**操作はすべてクライアント側で完結**させ、
Streamlit は配信だけを担当させている。

Streamlit Community Cloud にデプロイするときの設定値。

| 項目 | 値 |
|---|---|
| Repository | `muu4649/patent-casino` |
| Branch | `main` |
| **Main file path** | **`app.py`** |

`index.html` は生成物。編集するのは `src/template.html` で、変更後は `python3 build.py` を実行する。
